# 2026.10.19 球队统计总表公式引用错位（10.17）事故复盘

> 现行说明（2026-10-21）：本文保留事故发生时的数据及处理记录。10.17最新定案A90/B79，旧90:88不再作为生产依据；公式修复通过不等于字幕事实核验完成。

适用赛事：2026.10.17训练赛。同类文件排查建议先看本文件。

## 一、事故现象

用户反馈「数据统计表有问题」。体检发现 `球队统计总表` 的 SUMIF / SUMPRODUCT 公式
引用与实际数据不符，**表上的数字几乎全是错的**，但**没有报错、没有空值**，极难肉眼看出来。

## 二、根因：复制 10.04 模板后只改了一半

10.17 的表是从 **10.04 权威表**（那张公式是**全对**的）复制来的。复制时人名行数改了，
但**公式里的 4 类引用没重排**。逐个对比：

| 项 | 10.04（正确参照） | 10.17（出错） | 判 |
|---|---|---|---|
| 数据区行范围 | `$3:$275`（10.04 正好 273 行） | 大部分改 `$3:$313`，**罚球仍 `$3:$275`** | ✗ 漏改 |
| A队成员范围 | `$A$4:$A$12`（9人） | `$A$4:$A$9`（6人） | ✓ 已改 |
| B队成员范围 | `$A$14:$A$21`（8人） | **仍是 `$A$14:$A$21`** | ✗ 漏改（10.17 B队只有7人，在 `$A$11:$A$17`） |
| B队球员 SUMIF 第二参 | `A14`（自身行） | 行11→`A14`、行17→`A20`，**统一偏移 +3** | ✗ 漏改 |
| 中投组 H/I/J | 引用 `G/H/I` | 引用 `H/I/J`（+1 列） | ✗ |
| 远投组 L/M/N | 引用 `J/K/L` | 引用 `L/M/N`（+2 列） | ✗ |
| 罚球组 P/Q/R | 引用 `M/N/O` | 引用 `M/N/O` | 列对、行截断 |

## 三、六处具体错误

1. **中投组 H/I/J 错位 1 列**：`H`（中投出手）实际取的是 `中投命中`，
   `I`（命中）取的是 `中投得分`，`J`（得分）取的是 `远投出手`。
2. **远投组 L/M/N 错位 2 列**：`L`（远投出手）取的是 `远投得分`，
   `M`（命中）取的是 `罚球出手`，`N`（得分）取的是 `罚球命中`。
3. **罚球组 P/Q/R 行范围截断**：$3:$275，而罚球数据实际落在 **289 / 297 / 311 / 313 行**
   —— 全部在 275 之后，导致**全表罚球出手/命中/得分恒为 0**（本次损失最大）。
4. **B队每人罚球名字引用偏移 +3**：彭天乐取 `A14`=赵沐霖、梁源益取 `A15`=申铭赫……
   喻逸凡取 `A20`=**空白**，即申铭赫/许馨墨/喻逸凡三人的罚球恒为 0。
5. **B队合计范围 `$A$14:$A$21`**：只覆盖 赵沐霖/申铭赫/许馨墨/喻逸凡，
   **漏掉 彭天乐/梁源益/陈惟勤** 三人。
6. **两队合计「总时长 C」公式写错**：`COUNTIF($A$4:$A$9, 剪辑记录!$C$3:$C$313)`
   —— 用**时间列**去名单里匹配（永远 0），且 SUMPRODUCT 少第二个数组没乘时间，
   结果**恒为 0**。正确应对**球员名列** `$A$3:$A$313` 做 COUNTIF 再乘时间列。

> 派生影响：`T/U/V`（总投出手/命中/得分）与 `G/K/O/S/W`（各命中率）都依赖上面这些列，跟着全错。

## 四、修复

脚本 `_tmp_check/fix_stats_1017.py`：按 10.04 模式重写 420 个公式单元格——
数据区统一 `$3:$313`、A队 `$A$4:$A$9`、B队 `$A$11:$A$17`、每人引用自身行 `A{r}`。
先备份再改；`赛事 xlsx` 已追加《数据核对》修复记录行。

## 五、验收方法（强校验，推荐固化）

`_tmp_check/verify_fix_1017.py`：用 Python 按修正口径重算，**逐人逐项**比对
`summary_1017.json`（这是独立于表格的解析权威）。

结果：**13 人全部一致**（不只得分，含各项出手/命中/篮板/助攻/抢断/盖帽），
A队合计 90 / B队合计 88，与 json 完全吻合。

> 这条最关键：**勾稽通过不等于统计表对**。本次 `summary_1017.json` 自身勾稽是全对的，
> 剪辑记录明细也对，错只错在统计总表的公式引用上。所以验收必须做
> **「统计表 vs 权威 json」的逐人与合计双向比对**。

## 六、写进流程的硬要求

1. **任何新表由旧表复制而来，写完必须跑一次「统计表 vs summary_*.json」比对**，
   不能只看表里有数字就签字。
2. 行数/成员变化时，**四类引用必须一并重排**：数据区行范围、队伍成员范围、
   SUMIF 的球员名引用（必须 = 自身行）、分组源列。
3. openpyxl 写入公式**不带缓存值**，保存后需设 `wb.calculation.fullCalcOnLoad = True`，
   并在 Excel 打开确认重算结果。
4. 10.04 的表经核查**公式全对**，本次不需要返工；但
   **09.12 / 09.19 两张修正版同样值得用本方法体检一遍**。
