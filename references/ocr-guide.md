# 常青藤篮球字幕 OCR 识别全流程与精度提升手册

> **版本**：v1.0 ｜ **更新**：2026-10-21
> **用途**：任何智能体在「比赛录像 → 比赛剪辑表」环节做**字幕识别与解析**时的权威操作手册。
> 读完本文即可独立完成：抽帧 → OCR → 事件解析 → 人工核验 → 用户确认后封版 → 填表，并达到已验收的精度水平。
> 配套：《通用剪辑规范》《数据字典》《脚本使用说明》。

---

## 0. 为什么需要这份手册（先建立正确预期）

底部字幕 OCR 识别**不可能一次全对**。已验收的三场比赛（09.12/09.19/10.04/10.17）都是「机器识别 + 规则兜底 + 人工定帧核验」三层才达到全对。**识别精度差的智能体，差的不是 OCR 引擎，而是没有做后两层**。本手册把三层全部写清楚。

**核心原则**：
1. **OCR 识别 ≠ 事实**：OCR 输出只是候选，任何一条写入表格的数据都要能追溯到字幕原文或视频画面
2. **字幕窗口 = 字幕完整显示区间**（首帧~末帧），不是单帧；宁可多留独立事件，不可误合并
3. **表格时间是"参考"，视频字幕切换点才是"事实"**

## 1. 技术栈（用什么工具，已装好）

| 环节 | 工具 | 位置/说明 |
|---|---|---|
| 抽帧 | ffmpeg | 已在 PATH（8.x），`-vf fps=2,crop=...` |
| OCR 识别 | **Windows.Media.Ocr（系统内置引擎）** | 脚本 `00_流程与规范\脚本库\ocr\batch_ocr2.ps1`，无需安装任何第三方 OCR 库；中文模型随系统语言自动加载 |
| 事件解析 | Python（openpyxl 之外纯标准库） | `parse_1004_2fps.py`（10.04 通用版）/ `parse_1017_2fps.py`（10.17 括号版，含人工修正三表） |

| 定帧核验 | ffmpeg 抽帧 + 人工看图 | 抽字幕区放大图，交给用户/自己肉眼确认 |

## 2. 完整流程（五步，顺序执行）

```
① 抽字幕帧（2fps 必须）→ ② OCR 批量识别（Windows.Media.Ocr）
→ ③ 事件解析（合并去重 + 别名归一 + 得分归属）
→ ④ 人工定帧核验（Q 清单 → 用户确认 → 三表修正）
→ ⑤ 封版 → 填表 → 统计表体检
```

### 第①步：抽字幕帧（精度起点，参数不可改）

```bash
# 母带（合成后唯一源）→ 底部字幕区 2fps 抽帧，输出 t_0001.png 起
ffmpeg -y -i 合成母带.mp4 -vf "fps=2,crop=1920:160:0:920" -q:v 2 t_%04d.png
```

- **必须 2fps**：1fps 采样太稀会把字幕完整窗口压短（实测 0~6s 字幕被压成 2~3s）、空帧切断窗口。2fps 下窗口精度 **0.5s**
- **裁剪区 crop=1920:160:0:920**：只裁底部 160px 字幕条（x=0, y=920, w=1920, h=160）。全帧识别会引入场上球员、地板纹理等大量噪声，必须裁
- 帧号 → 秒：`t = (帧号 - 1) / 2`（如 t_0097 = 48.0s）
- 帧命名 `t_%04d.png`（4 位补零），供 OCR 脚本按序读取
- 视频长（如 715s → 1431 帧）；抽帧目录放 `01_比赛剪辑表\_数据源\01_抽帧\`

### 第②步：OCR 批量识别

```powershell
# 参数：帧目录 / 输出 CSV / 前缀 / 扩展名 / 起始帧 / 结束帧
powershell -File batch_ocr2.ps1 -FrameDir "D:\...\01_抽帧" -OutCsv "D:\...\02_OCR\ocr2_full.csv" -Prefix "t_" -Ext "png" -StartIdx 1 -EndIdx 1431
```

- 引擎 = `[Windows.Media.Ocr.OcrEngine]::TryCreateFromUserProfileLanguages()`（返回 NO_ENGINE 说明系统无中文 OCR 包，先装中文语言包）
- 输出格式：`帧号\t文本`（每行一帧）；识别失败的帧写 `<ERROR>`，不存在的帧写 `<NOFILE>`
- 每 100 帧自动落盘一次（防中断丢进度）；UTF-8 编码
- 识别结果含换行时压成空格；中英文混排直接给文本
- 产出：`ocr2_full.csv`（约 1431 行，一个字节一个事件线索）

### 第③步：事件解析（核心算法，含全部兜底规则）

**输入**：`ocr2_full.csv`；**输出**：`parsed_*.json`（`start_s/end_s/player/acts`，start_s/end_s 是真实字幕完整窗口）

```bash
python parse_1017_2fps.py   # 按当天名单定制别名表；10.04 用 parse_1004_2fps.py
```

解析器按以下顺序工作（全部为已调优参数）：

1. **预处理**：去空格；`OCR_FIX` 归一（如 `锄[-－—一]?\d?攻 → 助攻`、`甥板 → 攻板`）
2. **短乱码过滤**：文本长度 <6 的乱码帧直接跳过（如"一艹2"），不参与切段
3. **按标点切分**：`[，；、|,;]` 切成子句
4. **按名字切分**：子句内按别名最长优先匹配切出「名字+该名字的文本段」（别名表见《数据字典》+ 当天名单定制）
5. **动作识别**：正则容忍 OCR 错字（见下表"动作正则"），每个动作后紧邻 `+N` 取次数，无数字默认 1；`得分+N` 归属最近投篮者（last_shooter）
6. **连续帧合并**（同一条字幕的 OCR 抖动）：间隔 ≤5 帧（2.5s）且满足任一 → 同段：
   - 动作种类互为子集（容忍漏读/多读）
   - **共享任一名字且该名字有共同动作**（10.17 版新增，丢名/丢字时仍聚合）
   - 文本相似度 ≥0.85（difflib SequenceMatcher）
7. **组间合并**（修复双向漏读切段）：同上条件 + 间隔 ≤5 帧
8. **段内取众数**：同一字段多帧取值不同 → 取众数（防单帧数字误读）
9. **窗口 = 段首帧~末帧完整时间**（中间 OCR 空隙不压缩）
10. **后处理推断**：`得分+3` 且无任何出手 → 推断 `three=1`；`得分+2/+1` 无出手 → 进待核验清单 PENDING_CHECK
11. **三张人工修正表**（第④步确认后填入，脚本自动应用）：
    - `MANUAL_EVENTS`：OCR 丢字/漏帧的人工补录（start/end/player/acts/原因）
    - `FIX_EVENTS`：误归属覆盖（同窗口同人替换 acts）
    - `REPLACE_EVENTS`：误合并段拆分 / 冗余段删除（空列表 = 删窗口内全部行）

**动作正则（容忍乱码）**：

| 动作 | 正则 | 已知 OCR 变体 |
|---|---|---|
| 近投 | `[近蚯].{0,1}[投扌殳彭]` | 蚯投=近投 |
| 中投 | `[中冲].{0,1}[投扌殳]` | 冲投 |
| 远投 | `[远誆].{0,1}[投扌殳]` | 誆投（**10.17 实测"誆"多为"近"误读，需按拼图定夺**） |
| 罚球 | `罚.{0,1}[球篮]` | — |
| 攻板 | `攻.{0,1}[板舨]` | 甥板、舨 |
| 防板 | `[防舨].{0,1}[板舨]` | 防舨 |
| 助攻 | `[助锄怍].{0,1}攻` | 锄攻、锄-0攻、锄-=攻 |
| 抢断 | `抢.{0,1}断` | — |
| 盖帽 | `盖.{0,1}帽` | — |
| 得分 | `[得导].{0,1}分` | 导分 |

### 第④步：人工定帧核验（精度提升的关键，不可跳过）

解析后**所有修正/存疑点必须抽原帧确认**，流程：

1. 汇总成编号清单 **Q01~Q{n}**（文件名=问题描述，便于溯源）
2. 从母带按时间点抽**字幕区放大图**（2 倍宽便于看清）：
   ```bash
   ffmpeg -y -ss <T> -i 合成母带.mp4 -frames:v 1 -vf "crop=1920:160:0:920,scale=3840:320" Q17_xxx.png -update 1
   ```
3. 定帧图 + `核对清单.txt` 放入 `01_比赛剪辑表\_数据源\04_人工核验\问题定帧核对\`，**交用户核对**（用户能一眼看出"这个球是谁投的、进没进"）
4. 用户确认后 → 把结论写进 MANUAL_EVENTS / FIX_EVENTS / REPLACE_EVENTS → 重跑解析
5. **间隔帧检查**（得分事件切分后必跑）：相邻两条得分事件之间若只有空白/脏帧且同人同分值 → 疑似同一条字幕被切断（10.17 Q17/Q18 由此发现）或脏帧残留被当成新球（Q18），标黄人工确认

**对"识别效果差"的智能体的强制要求**：解析完成后，先读一遍输出的 `suspicious 明细` 和 `待人工核验` 清单（脚本会打印），**每一条都必须抽帧看，不能只看文本猜**。

### 第⑤步：封版 → 填表 → 统计表体检

- 用户确认全部 Q 清单后封版 → `fill_table_1017.py` 填入剪辑记录（24 列，见《通用剪辑规范》4.4）
- 统计表 vs `summary_*.json` 逐人逐项比对（`audit\audit_stats.py` + Python 复算）
- 数据勾稽：总得分 = 近×2 + 中×2 + 远×3 + 罚×1；命中数逐条对应"得分+N"字幕

## 3. OCR 常见误读类型与修正对照表（10.17 全量实测 16 点）

| 误读类型 | 实例 | 修正方法 |
|---|---|---|
| 投篮类型误读 | "誆投"实为近投（3处）/ 中投（1处） | 按拼图人工确认类型，写 FIX_EVENTS |
| 单字名误读 | OCR 把"雷奕梵"压成单字"雷"→ 得分 3 误归陈赞安 | 解析 ALIAS 补单字别名"雷"（**但单字别名有误归风险，仅当能唯一对应时加**） |
| OCR 丢字 | "远投+1"丢"远"字 | 补回投篮类型（MANUAL_EVENTS 或正则变体） |
| OCR 乱码 | "蚯扌得分+2"漏"近投+1" | 按"得分+出手紧邻"规则补出手 |
| 拆行丢数字 | "罚篮+2"拆行只记 1 次 | 按整段窗口人工数数字（看定帧拼图） |
| OCR 漏帧 | 8.5s 梁源益近投 / 482s 洪浩哲近投 | 人工补录 MANUAL_EVENTS（附原帧证据） |
| 名字抖动 | 单帧段"雷奕梵/喻逸凡"抖动 | 取拼图最完整帧确认归属 |
| 数字误读 | "助攻+1"读成"助攻+0"→ 误生得分 | 按字幕"助攻+1"修正、移除误归得分 |
| 重复事件 | 同(start,end,player)出现两行（OCR 补丁重复） | 填表时按动作次数合并去重 |
| 同一条字幕被空白帧切成 2 事件 | 梁源益「近投+1，得分+2」52.5~57s 被切 2 段各记 2 分 | **间隔帧检查** + 定帧同位同内容 → 删 1 条 |
| 脏帧残留当成新事件 | 申铭赫三分后 f1261 又完整出现同字幕 1 帧 | 同人 4.5s 内背靠背同分值 + 字幕文本完全相同 → 是残留不是新球 |
| 前板补篮被双人各记分 | 「A（近投+1）B（攻板+1，近投+1，得分+2）」 | 按括号归属：**只有 B 得分，A 只记出手** |
| 括号挡 + 号 | "喻逸凡(罚篮)+2，得分+1" | 括号内动作后无紧邻数字 → 按得分判定命中（2罚1中） |

## 4. 字幕格式与归属规则（已封版，10.17 用户锁定）

- **字幕物理格式 = 「人名+（数据统计）」**：括号内全部动作归括号前的人名；出现新「人名+（」即切换归属
- 例：`梁源益（近投+1），赵沐霖（攻板+1，近投+1）` → 梁源益近投 1；赵沐霖攻板 1 + 近投 1
- 无括号的历史字幕（09.12/09.19）：仍按"人名后动作归该人；新名字切归属；省略名字归最近具名者"
- **得分归属**：投篮子句后**紧邻**「得分+N」（中间无篮板/盖帽/人名切换）→ 该投篮命中，得分 N 归投篮者；若"得分+N"出现在另一名字括号内 → 归括号内名字（补篮）
- **失手**：投篮后出现攻板/防板/盖帽 → 最近未决投篮失手，篮板归具名者；段末仍无得分的未决投篮全记失手
- **多出手**：「近投+2」= 2 次出手；随后「得分+2」只记 1 次命中

## 5. 别名表维护（每场新比赛第一步）

复制 `parse_1017_2fps.py` → 按当天名单改 ALIAS 表，规则：

1. 收录该球员**全部已知 OCR 变体**（含错字、简称、漏字），别名**最长优先**匹配
2. **单字别名只加在能唯一对应的场景**（10.17 只加了"雷"；10.04 加了"唐/高/墨/杰"等——单字误归风险最高，宁缺毋滥）
3. 新场次识别出陌生变体 → 定帧确认后补进别名表，同时同步《数据字典》
4. 不同场次人员不同，**不要跨场复用别名表**（10.04 17 人表 ≠ 10.17 13 人表）

## 8. 避坑清单（已踩过的坑，禁止重犯）

| 坑 | 正确做法 |
|---|---|
| 用 1fps 抽帧 | 一律 2fps |
| 全帧识别（不裁剪） | 只裁底部字幕区 160px |
| 用 Tesseract 等替代 Windows OCR | 别换引擎；正则/别名都按 Windows OCR 调校 |
| 直接信 OCR 文本 | OCR≠事实；全部存疑点定帧核验 |
| 只抽查几名球员 | 全部球员、全部存疑点必须核验 |
| 把"得分"当"出手次数" | 得分只认「得分+N」；投篮动作只计出手 |
| 同一条字幕被切段还当两条 | 间隔帧检查：同人同分值相邻事件必查 |
| 前板补篮双人记分 | 括号归属，只有补篮人得分 |
| 相邻无缝字幕合并成一窗 | 球员集合变化必须断窗（10.04 c14 教训） |
| 文本相似兜底把不同字幕合并 | 共享名字+共同动作/文本≥0.85 才合并 |
| 定帧图分辨率不够 | 放大 2 倍（scale=3840:320），文件名含数字加 `-update 1` |
| 填表直接抄旧 18 列脚本 | 对照 24 列权威表列头，fill_table_1017.py 为准 |
| 人工核对表和解析层互当权威 | 权威只有字幕原文 + 视频画面；一致也要抽 3~5 条定帧盲核 |

## 10. OCR 预处理必踩三坑（09.12 重跑事故，2026-10-20 沉淀）

> 起因：另一个智能体对 09.12 重跑 OCR，把已基本正确的 142 分做到 89 分（事件 322→245、B 队 68→27）。
> 结论：**不是"重跑能修正"，而是"重跑把原本基本正确的结果做坏了"**。先诊断旧结果，别盲目重跑。

| # | 坑 | 实例 | 正确做法 |
|---|---|---|---|
| 1 | **一条字幕有两个人，只认第一个** | `杨卜权（远投+1），满铠睿（攻板+1，近投+1，得分+2）`——得分在第二人，只取第一个主语则 `得分+2` 整体丢失（投失+前板补中组合全场大量出现，补中者多为内线） | 按「人名+（动作列表）」**分段解析**，每段独立归属段首人名，禁止一条字幕只取一个主语 |
| 2 | **OCR 文本每个字符之间有空格，整串匹配必落空** | `杨 卜 权 （ 远 投 + 1 ）`，`杨卜权` 永远命中不了（实测命中 0 人次） | **先去空白再匹配，再做错字纠正**，顺序反了既漏又错 |
| 3 | **OCR CSV 两个格式坑** | ①第一行就是数据不是表头，跳过首行丢第 1 帧；②文本内英文逗号把一行切成多列（实测 257 处得分 1 处、415 处 7 处落到第 2 列后） | **按整行拼接取文本，不按列取**；不跳过首行 |

**脚本侧两个坑**：
- Bash heredoc 写正则会把 `\s` 变 `/s` 静默失效、扫描全 0 且不报错——**用文件写入工具写脚本，不用 heredoc**
- 噪声清洗正则**不能删全角逗号**（会把括号内动作粘连 → `得分` 永远匹配不到）——改成不含逗号，并用 `finditer` 扫全部匹配

**排查顺序铁律**：先修表格公式 bug（SUMIF 全指 A 列、B 队行整体错位一行的类问题），**否则 OCR 改对了表上也看不到正确数字**；用旧解析结果做基准反向校验重跑结果，逐人对比找缺口分布——**别只盯着差最多的队/人**（09.12 表面 B 队崩 −35，实际 A 队也漏 16 分，全场都漏）。

## 11. 四层对账法（前三层全过 ≠ 数据正确）

| 层 | 对账内容 | 揪出的问题 |
|---|---|---|
| ① 条数 | 字幕聚类事件条数 vs 解析条数 | 解析漏段（09.12：322 vs 245） |
| ② 总分 | 字幕所有「得分+N」求和 vs 解析求和 | 漏分/虚增 |
| ③ 归属 | 该球员**自己括号内**是否有得分（不是"窗口内出现过名字"） | 前板补篮双记 |
| ④ 间隔帧 | 相邻事件间只有空白/脏帧 且 同人同分值 | 同一条字幕被切断成两条 → 重复计分 |

- 三层对账全过也可能错在"事件切分层"（10.17 实证）：Q17 同字幕被空白帧切成 2 事件、Q18 脏帧残留被当新三分、Q19/Q20 前板补篮双人各记 2 分——**四层缺一不可**
- **人工核对表与解析层同源，不能互当权威**（10.17 人工 7 段核对表自身少记 3 分又保留 4 处虚增，就是因为它和解析共用同一份 OCR 文本）

## 12. 填表要点与回读校验（10.17 封版）

- **模板结构（10.04 最终权威版，24 列）**：A球员 / B开始 / C结束 / D-F近投(出/中/得) / G-I中投 / J-L远投 / M-O罚球 / P-Q-R总投(出/中/得公式) / S攻板 / T防板 / U总篮板(公式) / V助攻 / W抢断 / X盖帽；球队统计总表 A队紫底/B队橙底 + SUMPRODUCT/SUMIF
- **得分拆分**：先按本人括号及动作顺序归属；同一括号含多类投篮且只有合计得分时，用近2/中2/远3/罚1匹配可行组合（含2+1），唯一解写入，多解/无解标黄留空交用户。不得跨人拆分，也不得把同一得分重复加到多个类别。
- **人数不同**：删多余行后重写公式区间（队头名单区 + 剪辑记录数据区 `$3:$N`）
- **`fill_table_1004.py` 是旧 18 列格式，与权威表（24 列含得分列）不一致——用前必须对照权威表列头，禁止照抄；24列结构参考 = `fill_table_1017.py`（现存脚本仍有旧路径、三分命中除数误用2等缺陷，修正并审计前不可直接运行）**
- **同(start,end,player)重复事件**：合并 acts 次数后再填
- **回读校验**：汇总脚本必须用 `+=` 累加得分（曾用 `=` 只回读最后一行，误报得分全 0，浪费一轮排查）；`excel_formula_verify.py` 无 LibreOffice 时退出码 4 属正常终态（只读诊断），交付说明写明需在 Excel 内刷新公式
- **10.17 定案比分 A90 : B79**：B 队 −9 分全部来自四类虚增（Q17 同字幕切断 −2、Q18 脏帧残留 −3、Q19/Q20 前板补篮双记各 −2），定帧图实锤存 `04_人工核验\问题定帧核对\`；A 队与用户记忆 89 差的 1 分在字幕层面无法定位，按用户确认值 90 定案不再追查
